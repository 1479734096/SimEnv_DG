## 5. 为什么 PATH 模式没有死区补偿？

### 推测 1: 时间先后关系
- ALIGN 模式可能是后开发的
- 在开发 ALIGN 时才发现死区问题
- 修复 ALIGN 后忘记回溯修复 PATH

### 推测 2: 使用场景差异
- ALIGN 是**纯转向**（linear=0），死区问题更明显
- PATH 有**前进速度**，死区影响可能不明显（在某些 seed 中）
- 开发者可能认为 PATH 不需要死区补偿

### 推测 3: 代码位置隔离
- ALIGN 在类方法 `_align_tick_rotate()` 中（行 900+）
- PATH 在独立函数 `compute_tracking_command()` 中（行 1517+）
- 两者隔离，修复一个时没想到另一个

### 推测 4: seed 覆盖不足
- 早期测试的 seed 可能恰好不触发 PATH 死区问题
- seed 707 成功强化了"PATH 正常工作"的印象
- 直到运行 seed 8127/42/8072/2024 才暴露问题
