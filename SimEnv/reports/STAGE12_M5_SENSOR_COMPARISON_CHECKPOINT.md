# 第 12 层 M5 检查点：RGB-D/Livox 同窗对比

## 1. 结论

M5 离线分析工具已完成，可以进入随机多 seed 数据采集；当前没有修改生产定位行为，
也没有得出“Livox 应替换 RGB-D”或“应调整融合权重”的结论。

原 M3 两轮证据位于 `/tmp`，在会话中断后已被环境清理。M5 曾开始回放这些 bag，
但输出同样随 `/tmp` 消失，无法复核，因此不得把未保存的中间结果写入结论。后续数据
必须由预登记的随机 seed 重新采集。

## 2. 实现内容

`tools/offline/analyze_localization_quality_bag.py` 新增以下只读分析能力：

- 解析 RGB-D 与 Livox 相邻帧 GICP 的接受状态，只统计已接受且实际产生位移的帧；
- 以固定 `0.5 s` 窗口按帧中点归桶，要求两路时间覆盖率都至少为 `60%`；
- 用插值后的同窗真值位移分别计算两路平移误差，避免不同频率和最近邻时间误差；
- 把误差投影到机器人前向/侧向，不使用固定世界 X/Y 符号作生产候选；
- 分别统计整体、低转角、高转角、电梯换层及出厢后五秒、各任务阶段；
- 输出 RMSE、P95、前后/侧向偏差、积分终点误差和 Livox 相对改善率；
- 对最大 `2 s` 漂移增长窗口记录定位与离线真值起终点、楼层/任务阶段、两路位移、
  scan-to-map 累计校正、转角、深度新鲜率和局部结构退化程度；
- 新增 `--sensor-windows-csv`，保存逐窗证据供跨 seed 汇总。

## 3. 冻结判定门槛

单轮只有同时满足以下条件，才标记为 Livox 主链候选：

1. 有效运动公共同窗不少于 20 个；
2. Livox 相对 RGB-D 的 RMSE 和 P95 都至少改善 `15%`；
3. 低转角窗口 Livox RMSE 不得比 RGB-D 恶化超过 `5%`；
4. 公共同窗累计终点误差必须改善。

单轮通过不进入生产。至少两个预登记的不同 seed 方向一致，且完整任务指标无明显回归，
才允许设计一个默认关闭、质量缺失时回退现状的生产候选。

- 生产节点和正式 launch 没有新增话题、文件、TF、服务或真值依赖；
- 未修改赛方 SimEnv、Unitree、传感器、生成器或既有说明文档；
- 分析器不能被生产包导入，输出也不会反馈到当次任务决策。

## 6. 下一步

1. 一次性随机生成并提交 seed 清单，运行前冻结，不按结果挑选；
2. 每个 seed 使用相同双层、双向电梯、返航配置，采集逐帧定位诊断、`/scan`、内部
   odom 和独立离线真值；
3. 逐轮输出整体误差和最大漂移增长的位置、阶段、方向与候选原因；
4. 至少两轮有效数据方向一致后，才选择 Livox 主链、GICP 平移约束或跨层地图生命周期
   中的一个单机制候选；
5. 若无候选满足门槛，记录阻断并保留当前生产定位，不扫参数。
