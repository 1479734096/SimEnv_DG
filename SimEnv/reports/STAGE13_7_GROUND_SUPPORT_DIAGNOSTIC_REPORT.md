# STAGE13.7 生产防坠速度语义与 UNKNOWN 边界诊断报告

## 1. 阶段结论

本层只做代码、文档和 STAGE13.6 同轮 bag 的离线诊断，没有修改生产行为、配置、launch、
测试或官方文件。

当前生产防坠不能封板，原因不是单一阈值，而是停车包络中的“速度”同时承担了互不兼容
的职责：

- `PoseSample.planar_speed` 来自 1 秒定位位姿差分，不是底盘物理速度反馈；
- 它在真实已停时可能因定位窗口滞后而偏大，在制动瞬间也可能低估真实速度；
- 当前代码却同时用它选择停车距离、判定超出已验证速度域和确认停稳。

同轮数据支持保留“连续三帧低定位速度可作为停稳证据”，但不支持把定位差分速度继续
称为或当作物理速度上界。当前停车表也缺少可追溯的动态测量报告，不能据此声明
`0.651 m/s` 已验证。

因此出现两个互斥方向：

1. 保持 formal 安全门开启，把包络语义收敛为“控制请求速度 → 包含底盘响应的实测制动
   距离”，定位速度只负责有界异常观察和多帧停稳确认；
2. 按 `fix.md` 既定保守条款，在完整制动与真实空带证据补齐前取消 formal 强制开启，
   避免生产系统宣称一个尚未验证的防坠保证。

这是生产安全架构选择，本层不擅自决定。

## 2. 真实调用链

生产链为：

```text
/cmd_vel 请求
  → PathFollower 唯一速度出口
  → GroundSupportSafetyGate.filter_command()
  → junior_ctrl

/scan + 内部定位
  → ShadowSupportGrid
  → GroundSupportAssessment
  → GroundSupportSafetyGate

/danger_search/localization/odom.twist
  → PoseSample.planar_speed
  → GroundSupportSafetyGate.observe_odometry()
```

`scan_localization_node` 的 `Odometry.twist` 由 `PoseVelocityEstimator` 对世界位姿做
`1.00 s` 窗口差分，最小有效间隔 `0.80 s`，再转到 base 系。该速度会包含 GICP 与
scan-to-map 对位姿的平移校正，不是独立轮速、腿速或物理真值。

公开比赛接口没有合规的机体线速度反馈。`/Odometry_gazebo`、`/ground_truth/*` 和
Gazebo model state 均禁止进入生产。IMU 不能在无可靠零偏约束下积分出可用于停车保证的
平移速度，因此“换成 IMU 积分速度”不是合规解决方案。

## 3. STAGE13.6 同轮速度证据

证据：

- `/tmp/stage13_6_health_seed6946/elevator_diagnostic.bag`
- seed `6946`
- 完整 `0→1→0→home`
- 真值只由独立 rosbag 录制，以下比较均在任务结束后离线完成。

将 1651 个定位样本与最近的 `/cmd_vel` 和 `/ground_truth/base_w` 对齐：

- 定位速度与真值速度绝对误差：P50 `0.0297 m/s`、P95 `0.2786 m/s`、
  P99 `0.3574 m/s`、最大 `0.4150 m/s`；
- 当真值速度不大于 `0.05 m/s` 时，定位速度 P95 仍为 `0.2215 m/s`，最大
  `0.4390 m/s`；
- `max(请求速度, 定位差分速度)` 仍有 151 个样本低估真值超过 `0.02 m/s`，
  35 个超过 `0.05 m/s`，13 个超过 `0.10 m/s`；
- 真值速度峰值 `0.7607 m/s`，高于当前表末档 `0.651 m/s`；同一时刻请求速度约
  `0.556 m/s`，定位差分速度约 `0.453 m/s`。

这证明：

- 定位差分速度不能提供可靠的瞬时物理速度上界；
- 仅以“控制上限 `0.60 < 0.651`”证明实际速度位于验证域内也不成立；
- 单纯提高定位速度滤波或超界确认次数只会改变误报/漏报比例，不能修复速度语义。

## 4. 停稳证据与停车表边界

同轮中查找“请求线速度和角速度持续为零，定位线/角速度连续三帧低于现有停稳阈值”的
15 个独立片段：

- 对齐真值线速度全部低于 `0.021 m/s`；
- 没有一次超过当前 `0.05 m/s` 停稳阈值。

因此现有“三个新 odom 样本确认停稳”在这一轮有正证据，可以继续作为候选停稳判据，
但仍需第二个独立 seed 复核，且不能扩张成“定位速度是物理速度上界”。

进一步筛选 13 次从非零前进请求切换到线、角命令持续全零直至真值停稳的事件：

- 真值停车距离 P50 `0.0554 m`；
- P95 `0.0779 m`；
- 最大 `0.0803 m`；
- 这些事件的初始真值速度最大约 `0.569 m/s`。

该结果在本轮范围内低于当前 `0.60 m/s → 0.0934 m` 表项，但还不能验证：

- 请求 `0.60 m/s` 时底盘真实速度峰值对应的停车距离；
- `0.651 m/s` 表项的来源；
- 不同 seed、直行/弧线、门槛和电梯地面上的最坏制动；
- 真实 DROP 触发后从检测、零命令到完全停稳的总前向位移。

仓库历史只显示停车表在第 8 层配置落地；第 2、4 层报告反而明确写着动态停车距离留待
后续完整动力学复核。没有找到生成 `0.093377...` 和 `0.101958...` 的原始测试工具、
bag、计算过程或阶段报告，所以“已验证停车包络”的既有表述证据不足。

## 5. STAGE13.6 的 UNKNOWN 边界事件

94.46 秒开始的安全事件不是 `DROP_CONFIRMED`：

- 当前足印始终受支撑；
- `drop_confirmed=false`；
- `true_drop_stop_count=0`；
- 支撑前缀约 `0.20 m`，前方存在 UNKNOWN 支撑边界；
- 配置在停车距离与时延余量外另加 `boundary_hold_margin=0.30 m`，因此进入
  `OBSERVATION_HOLD/STALE_DATA_HOLD`；
- 2 秒内边界没有稳定变成足够远的正支撑，99.16 秒进入
  `SUPPORT_PATH_UNAVAILABLE` 并清除当前路径；
- 之后预算状态切换到返航，任务完成。

这条链符合当前“UNKNOWN 超时只让当前路径失效”的设计，不是陈旧时间重复计算 bug。
但它也不是生产防坠端到端证据：没有明确低层回波、没有 DROP 锁存、没有负障点写入和
DROP 后局部重规划。

## 6. 已证伪与禁止继续尝试

已证伪：

- “定位差分速度经过 1 秒窗口后可视为物理速度上界”；
- “控制请求不超过 `0.60 m/s` 即可证明真实速度不超过 `0.651 m/s`”；
- “STAGE13.6 的一次 UNKNOWN 路径清除等价于真实 DROP 闭环”。

不得继续：

- 增加超界确认次数来掩盖定位速度语义错误；
- 放宽停稳阈值；
- 用 IMU 平移积分伪造速度；
- 在没有可追溯实测的情况下添加高速停车表项；
- 关闭 UNKNOWN hold、降低 DROP 几何门槛或缩小安全余量来换取零误停；
- 用固定 seed、固定世界坐标或修改 world 构造空带。

## 7. 最小复核实验

在选择生产架构前，建议先补一项不进入生产的诊断工具，并运行两轮独立测量：

1. 离线工具同时读取 `/cmd_vel`、内部定位 odom、`/trunk_imu` 和独立真值 odom；
2. 按“线、角命令持续全零”分割制动事件，分别报告请求档位、真值初速、停车时间、
   前向停车距离、二维路径长度、定位停稳确认时刻和确认时真值速度；
3. 至少覆盖两个 seed、直行和弧线，单轮必须包含接近 `0.60 m/s` 的稳定请求；
4. 预先定义验收：两轮所有定位三帧停稳确认对应真值线速度均不大于 `0.05 m/s`；
   停车表取同请求档位两轮最大前向距离的保守上界，并保留正余量；
5. 另用合成负障节点级闭环验证
   `DROP_CONFIRMED → 唯一出口零速 → 三帧停稳 → 路径失效 → 有界重规划/失败`；
6. Gazebo 只允许在合法生成场景中由传感器自然发现空带；若两轮没有自然触发，
   记录为缺证据，不传送机器人、不改 world。

完成上述测量前，不进入覆盖提速，也不宣称生产防坠封板。
