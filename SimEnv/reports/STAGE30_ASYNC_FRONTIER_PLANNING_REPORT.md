# STAGE30 探索前沿异步规划报告

## 目标

消除普通前沿 A* 对 10 Hz 任务主循环的阻塞，并在活动路径执行期间每 3 秒进行一次机会性重评估。机器人接近当前前沿时，根据近期规划耗时和路线推进速度提前计算下一目标，减少到点停车等待。

## 实现

- 普通前沿、机会性重选和到达前预规划共用一个后台规划线程；门、电梯、危险源接近及运动控制保持原有同步语义。
- 后台只读取 `FloorGrid.copy()`、不可变规划约束和独立 `FrontierExplorer` 副本，不访问实时地图、控制器或任务状态。
- 主线程提交结果前检查楼层、地图周期、定位周期、约束版本、路径代次和活动目标，并在实时地图上重新验证前沿收益及全部路径线段。
- 机会性重选周期为 3.0 秒，继续使用既有区域迟滞和 `switch_score_margin: 3.5`；进入预规划窗口后暂停机会性任务，为下一目标让出线程。
- 提前量采用最近 20 次有效规划墙钟耗时的 P90 加 0.25 秒，限制在 0.5～3.0 秒。路线 ETA 根据剩余折线路程的墙钟下降速度估计；没有新鲜正向进度时不投机规划。
- `PathFollower` 新增线程安全生产快照，规划逻辑不读取诊断字典，也未增加新的 `/cmd_vel` 发布者。
- 单次后台规划超过 5 秒后隔离迟到结果；若控制器已经到点，则消费终态并保持零速，避免等待线程造成任务死锁。

## 合规检查

- 未新增外部话题、服务、文件输入或 TF 依赖。
- 未读取 `/ground_truth/*`、`/Odometry_gazebo`、world、truth 或布局 metadata。
- 速度输出仍只经过 `PathFollower` 的既有统一出口。
- 后台线程产生的日志和失败增量必须先经主线程作用域校验，过期结果不会修改实时状态。

## 风险与下一步

- 到达前候选是基于短时地图快照的投机结果；实时复核失败时会安全退回普通异步规划，因此仍可能出现一次短暂停车。
- Python 线程无法安全强杀；超时任务会被标记过期并在最终返回时回收，有限栅格 A* 仍受现有搜索边界约束。
- 后续双楼层长测应统计主循环周期、机会性切换次数、预规划命中率、到点停车时长和路径折返距离，并重点确认电梯及门任务期间没有探索规划结果越权提交。
