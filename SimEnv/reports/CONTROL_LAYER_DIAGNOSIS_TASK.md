# 控制层系统化诊断任务

## 目标

深度分析控制层问题，为重构提供完整的问题清单和架构设计。

**已知问题**（来自 Phase 1 验证）:
1. PATH 模式死区补偿缺失 → 原地摆动
2. IDLE/rotate_in_place 死区补偿缺失 → 返航卡住
3. 电梯导航失败：`elevator_navigation_unreachable`
4. 探索停滞：simtime 120s, 151s, 217s, 269s

**已有修复参考**（在当前分支）:

**用户需求**: 一次性从根本解决问题，不再反复测试微调

## 诊断范围

### 1. 控制模式分析（30 分钟）

**任务**: 梳理所有控制模式及其命令生成路径

**关键问题**:
- 有哪些控制模式？(PATH/IDLE/ALIGN/其他)
- 每种模式在什么场景下触发？
- 每种模式的运动命令如何生成？
- 是否有统一的控制律接口？

**输出**: 控制模式清单和调用关系图

### 2. 死区补偿覆盖分析（30 分钟）

**任务**: 分析死区补偿在各模式的覆盖情况

**关键问题**:
- 哪些模式有死区补偿？
- 补偿参数是否一致？(0.55 rad/s)
- 补偿触发条件是否统一？
- 是否有遗漏的控制路径？

**输出**: 死区补偿覆盖矩阵

### 3. 电梯导航失败分析（45 分钟）

**任务**: 深入分析 `elevator_navigation_unreachable` 的根因

**数据源**:
- Phase 1 日志：`/tmp/phase1_quick_8127/mission.log`
- 关键时刻：simtime 288-354s

**关键问题**:
- 为什么第一次能到达电梯门，刷新后不可达？
- 障碍物膨胀参数是多少？
- 是控制层问题还是规划层问题？
- 电梯门位置刷新逻辑是否合理？

**输出**: 电梯导航失败的根因和修复建议

### 4. 探索停滞分析（45 分钟）

**任务**: 分析多次探索停滞的共同模式

**数据源**:
- Phase 1 日志：simtime 120s, 151s, 217s, 269s 时刻

**关键问题**:
- 停滞时机器人在做什么？(IDLE/等待/决策?)
- 是 frontier 选择问题还是控制执行问题？
- 是否与死区补偿相关？
- 是否有超时或重试机制？

**输出**: 探索停滞的根因和修复建议

### 5. 架构设计（30 分钟）

**任务**: 基于诊断结果，设计控制层重构方案

**设计要点**:
- 统一的控制律接口
- 统一的死区补偿策略
- 清晰的模式切换逻辑
- 完整的边界条件处理

**输出**: 控制层架构设计文档

- `src/danger_search/danger_search/navigation_tasks.py`（任务层）
