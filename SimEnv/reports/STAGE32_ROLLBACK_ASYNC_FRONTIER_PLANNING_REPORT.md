# STAGE32 探索前沿规划回退同步模式报告

## 1. 概述与结论

根据实测评估与任务稳定性要求，本阶段将探索前沿规划从 STAGE30 引入的异步多模式规划（`async_planning_enabled: true`）**回退至经典同步单次规划模式（`async_planning_enabled: false`）**。

* **回退后行为**：机器狗恢复为到点完全停稳、在主线程同步调用 `select_frontier` 计算一条完整路线后起步，沿该路径专注执行至目标点；关闭行进中换道（`MODE_OPPORTUNISTIC`）与到达前预规划（`MODE_PREFETCH`）。
* **测试验证**：全量单元测试 **857 passed**（0 失败），边界审计 100% 通过。

---

## 2. 回退根本原因分析

在双楼层仿真长测（`seed=8127`）中，异步前沿规划与高速运动控制、底层地面安全门及点云建图产生了以下三方面的连锁冲突：

### 2.1 动态点云稀疏与防坠安全门（GroundSupportGate）冲突
* **现象**：机器狗在进入走廊尽头（`y ≈ 12.5m`）时，频繁在两个房间目标之间来回换道、反复横跳。
* **原因拆解**：
  1. 异步规划消除了到点停车，机器狗在以 $0.80\,\text{m/s}$ 高速不间断奔跑时，Livox 激光雷达点云对前方 $1.0\,\text{m}$ 足迹带的投影属于动态实时更新；
  2. 当遇到走廊转角或门洞视场盲区时，足迹带点云在短时间内覆盖不足，触发防坠安全门的观察停车（`OBSERVATION_HOLD`）；
  3. 由于盲区超时设为 $2.0\,\text{s}$，安全门出于 Fail-closed 保护判定为前方不可通行（`ground_support_path_unavailable`），强行掐断当前路径；
  4. 路径被打断后，规划器被迫将当前目标拉黑并改选对侧目标；而在对侧走廊遇到相同盲区时再次被打断，造成两目标之间被动来回横跳。

### 2.2 高速运动机身颠簸导致地面误判为障碍物
* **现象**：地图在走廊与开阔地面上出现大量虚假障碍物核心（`hard_core_count > 4000`），将原本可通行的路面堵塞。
* **原因拆解**：
  1. 四足狗在 $0.80\,\text{m/s}$ 高速奔跑及大角度弧线转弯时，腿部交替踏步带来机身前后俯仰（Pitch 振幅达 $3^\circ \sim 5^\circ$）；
  2. 激光雷达随机身倾斜，打在前方 $2 \sim 5\,\text{m}$ 处的平整地面点云在坐标系投影中被虚假抬高 $15 \sim 25\,\text{cm}$；
  3. 当高程超过 $z \ge 0.20\,\text{m}$ 时即被建图模块误判为障碍物，超过 $0.40\,\text{m}$ 时直接被判定为单帧生效的 `HIGH_HARD` 硬障碍并向外膨胀 $0.25\,\text{m}$，堵死走廊通道；
  4. 假障碍物阻挡了后续的自由射线洗地（`free_clear`），导致地面虚假障碍物固化残留。

### 2.3 经典同步单次规划模式的静态物理优势
* **静态满格点云**：在同步模式下，机器狗每到达一个目标点都会完全刹停零速 $300 \sim 500\,\text{ms}$。在静止水平姿态下，激光雷达持续积累饱满点云，地面支撑覆盖率达到 100%，不会触发盲区 Hold；
* **静止深度洗地**：到点停稳期间的连续激光射线会将沿途偶发的地面噪点彻底冲刷清空；
* **绝对稳定跟踪**：起步后机器狗 $100\%$ 专注跟踪当前路径直至到点，主循环跳过前沿提取，从根本上杜绝了运动中被动换道与横跳。

## 3. 配置变更

在 `SimEnv/src/danger_search/config/danger_search.yaml` 中将异步规划总开关置为 `false`：

```yaml
frontier:
  # 恢复为经典同步规划模式，关闭后台规划线程、行进中换道与到达前预规划
  async_planning_enabled: false
  opportunistic_replan_period: 0.0
```
