# STAGE16 共享地图事务式自适应定位报告

## 1. 结论

本阶段实现了默认关闭的 `adaptive_shared_map` 实验后端。三组固定 seed 都完成了
闭环，但当时因错误地用相同时间、不同路程的数据比较 seed `8072`，提前停止了后续
矩阵；因此该阶段没有形成足够的默认晋级证据，正式 `danger_search.launch` 继续默认
使用 `rgbd_livox`。

- seed `8127`：候选 RMSE 从 `0.07897 m` 降至 `0.06502 m`，完整闭环成功；
- seed `1612`：候选 RMSE 从 `0.49640 m` 降至 `0.07068 m`，完整闭环成功；
- seed `8072`：候选任务从主入口失败改善为完整闭环；按基线实际走过的同一
  `1.529 m` 路程比较，RMSE、P95、末端误差分别改善 `24.3%`、`15.8%`、`1.9%`；
- Stage16 停止 seed `6946` 的依据不成立。保留“不扫阈值、不增加 seed/阶段特例”约束，
  但应通过预登记的大样本固定矩阵决定是否切换正式默认。

## 2. 原因、方案、目的

| 原因 | 实施方案 | 目的 |
|---|---|---|
| RGB-D 与 Livox 分别累计平移，直接切源会带入坐标偏差 | 两路都相对同一张 Livox 局部地图输出绝对平移候选 | 让候选可比较，避免切源跳变 |
| 原匹配器把估计与地图写入绑定 | 拆成只读 `EstimateFrame()` 与 generation 校验的 `CommitFrame()` | 防止过期或未选中候选污染地图 |
| IMU 姿态稳定但加速度积分漂移 | `/trunk_imu` 始终定姿，不积分线加速度 | 保留稳定 yaw，避免位置双积分 |
| 两类点云各有局部退化窗口 | 同意时选 RGB-D，分歧超过 `0.05 m` 时选 Livox，单路有效时使用该路 | 按实时观测质量选源，而不是按任务阶段猜测 |
| 两路都无效时发布旧位姿会掩盖故障 | 不更新地图、位姿和时间戳，不发布 odom/cloud | 让现有定位陈旧门真正 fail-closed |

## 3. 实现

- `ImuConstrainedOdometry` 增加只读估计、地图代次、显式正式位姿运动参考和事务提交；
  旧 `RegisterFrame()` 保留为兼容包装，正式 `rgbd_livox` 行为不变。
- 新增纯逻辑 `AdaptiveTranslationSelector`，覆盖双路同意、分歧、单路回退、过期、
  非有限数、错误 generation 和地图提交距离门。
- RGB-D 回调只读共享地图并缓存一次性候选，不发布位姿、不写地图；Livox 回调是唯一
  输出时钟和地图写入入口。
- 地图只允许当前 Livox 帧按最终正式位姿提交；generation 不匹配时整帧拒绝。
- 新后端复用公开 `/scan`、`/trunk_imu`、`/real_sense/depth/points` 和自身
  `/cmd_vel`，没有新增依赖、外部话题、TF 或禁用输入。
- launch 和 runner 只增加后端白名单及三个实验参数；正式默认保持 `rgbd_livox`。

### 4.2 输出连续性与选源

| seed | 平均 odom 频率 | 最大间隔 | RGB-D 选中 | Livox 选中 | 双路无效累计 |
|---|---:|---:|---:|---:|---:|
| 8127 | `9.89 Hz` | `0.204 s` | 201 | 1413 | 18 |
| 1612 | `9.99 Hz` | `0.198 s` | 117 | 1492 | 1 |
| 8072 | `9.99 Hz` | `0.302 s` | 59 | 1527 | 2 |

三轮都满足平均频率不低于 `8 Hz`、正常传感器期间最大间隔不超过 `0.5 s`，没有因
定位陈旧或三秒不可用失败。出现过的短暂 `STALE_DATA_HOLD` 来自
`ground_support_stale`，随后自动恢复，不是定位输出中断。seed `8127` 诊断 bag 中
`/scan` 为 1647 帧、`/trunk_imu` 为 64113 帧、内部 odom 为 1608 帧。

RGB-D 选中占比分别约 `12.5%`、`7.3%`、`3.7%`。大量 RGB-D 结构帧在共享地图中因
有效点或对应点不足被拒绝，第一版的实际行为仍明显偏向 Livox。它证明了共享状态、
事务提交和 fail-closed 能稳定运行，但没有证明双源能高比例互补。

## 5. 根因与裁决

1. 共享地图消除了独立累计后切源的坐标状态分叉；三轮最大输出间隔均小于 `0.5 s`，
   没有频繁触发定位停车，说明 fail-closed 本身不是主要退化来源。
2. IMU 直接定姿继续有效。三轮候选最大 yaw 误差均小于预登记的 `0.005 rad`。
3. 平移仍由局部地图几何决定。RGB-D 可用率低时，候选接近 Livox-IMU 局部地图方案；
   走廊、门区和重复结构中的统计合理错误仍可能被接受。
4. seed `8072` 的原共同时间窗口混入了 `79.4%` 的路程差，不能作为逐 seed 退化证据；
   同路程重算反而改善，但三组 seed 仍不足以证明总体稳定性。
5. 任务阶段不是可靠的几何质量代理。三轮的好坏窗口跨越主入口、普通走廊和二层，
   因此不增加“电梯/楼层固定选 RGB-D 或 Livox”的特例。

裁决：保留 `adaptive_shared_map` 作为默认关闭、可审计的实验后端；Stage16 不修改正式
默认，不围绕 seed `8072` 扫描 `0.05 m` 阈值。后续应冻结实现与门槛，补完包括
seed `6946` 在内的预登记矩阵。

## 7. 缺陷、风险与下一阶段入口

- RGB-D 结构候选可用率过低；下一步应先离线量化“采样后结构点数、有效对应数、视场与
  地图覆盖”的损失链，再冻结一个不使用真值的候选质量规则，不能直接降低最小点数。
- 局部地图没有回环和全局重定位；在前端逐 seed 稳定前，不引入 LIO-SAM/Pose Graph
  掩盖局部错误。
- 当前点云没有可信逐点时间，不能直接接 FAST-LIO2 的逐点去畸变和 ESKF 生产链；若
  后续获得官方明确的逐点采样时间语义，再单独评估依赖和接口变更。
- 正式默认继续 `rgbd_livox`。任何提升 `adaptive_shared_map` 的后续阶段必须冻结规则，
  使用同配置、同任务闭环的固定 seed 矩阵评估；短窗对照必须按同路程或同任务阶段匹配，
  不能再次用相同时间但不同运动进度的数据裁决。
