# 第 14.2 层：逐帧分歧反事实与生产候选阻断报告

## 1. 阶段结论

第 14.1 层证明了 RGB-D/Livox 的 `0.5 s` 分歧模长能跨 seed、跨路线区分
RGB-D 高误差窗口，但该结果没有证明应怎样修改累计定位。本层在查看结果前冻结逐
RGB-D 帧的因果特征、质量回退、阈值和验收门，并比较两种最小累计动作。

结论是：特征的逐帧区分能力仍成立，但两种累计动作都没有跨运行稳定收益。四轮中只有
`m5_seed8072` 通过；其余三轮的累计定位 RMSE 明显恶化。因此：

- 不修改 `scan_localization_node.cpp`；
- 不新增生产参数、订阅或状态；
- 不运行 Gazebo；
- 按“同一逻辑两次无稳定收益即停止”关闭“直接替换/丢弃异常 RGB-D 增量”路径；
- 定位专项恢复为暂停状态。

## 2. 生产实现审计

只读核对 `src/danger_search_localization/src/scan_localization_node.cpp` 后确认：

1. RGB-D 和 Livox 分别累计到世界系 `depth_total_` 与 `livox_total_`。
2. RGB-D 新鲜时，融合位置为
   `depth_total_ + depth_fusion_offset_`。
3. RGB-D 过期时，才使用
   `fused_at_last_depth_ + livox_scale_ * (livox_total_ - livox_at_last_depth_)`。
4. scan-to-map 校正同时写入融合位置、RGB-D offset 与最近 RGB-D 锚点。
5. 现有约一秒尺度窗口只更新 Livox 尺度，不能为单个 RGB-D 增量提供即时裁决。
6. 现有状态没有“最近已接受 Livox 帧区间”的生产缓存；在证明锚点语义前新增该状态
   会扩大行为面。

因此，不能把第 14.1 层的事后窗口 AUC 直接解释成可安全接入的源切换门。

## 3. 冻结口径

本层在读取四轮结果前冻结：

| 项 | 冻结值 |
|---|---:|
| RGB-D 原生帧区间 | `0.10～0.35 s` |
| Livox 同窗最低覆盖率 | `60%` |
| Livox 因果边界 | Livox 帧结束时间不得晚于当前 RGB-D stamp |
| 分歧特征 | `hypot(rgbd_delta - livox_delta)` |
| 触发阈值 | `0.05 m` |
| RGB-D 低/高误差标签 | `<=0.02 m` / `>=0.05 m` |
| 局部 RMSE 最低改善 | `15%` |
| 高误差最低召回 | `50%` |
| 低误差最高误触发 | `5%` |
| 累计定位门 | 候选 RMSE 不得高于原始 RMSE |
| 质量缺失 | 完全回退现有 RGB-D 行为 |

没有使用真值选择阈值；真值只用于任务结束后的离线标签和误差计算。

两种动作是：

1. `livox_substitution`：触发帧以同窗 Livox 增量替换 RGB-D 增量并持续累计；
2. `hold_position`：触发帧不累计 RGB-D 平移。

第二种动作是同一特征假设下唯一更保守、且不引入第三来源的对照。两种动作都失败后
停止，不继续尝试连续帧、滞回、阈值或 offset 扫描。

## 6. 因果解释边界

局部帧误差更小而累计误差更大，不矛盾。按分歧触发选择 Livox 会形成条件选择偏差：
单帧误差模长虽小，累计误差向量仍可能长期同向。历史 scan-to-map 校正又是在原始
融合轨迹和原始局部地图上产生的，离线固定校正不能完整模拟行为改变后的地图反馈。

这带来两个同时成立的结论：

1. 当前反事实足以否决“直接替换或直接丢弃即可安全改善”的主张；
2. 当前反事实不能证明某个尚未定义、包含地图重放的复杂锚点机制一定无效。

第二点不构成继续写生产代码的授权。要恢复该方向，必须先有能重放 scan-to-map
反馈的离线模型，并在看结果前冻结唯一锚点语义；不得把本轮全局退化归咎于工具后直接
忽略累计门。
