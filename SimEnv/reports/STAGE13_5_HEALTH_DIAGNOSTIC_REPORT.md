# 第 13.5 层：定位姿态健康门误报诊断报告

## 1. 结论

第 13.3 层返程失败不是 IMU 检出的真实倾倒，而是持续姿态健康门把一份不可靠的
Livox 斜面拟合直接当成了机身坏姿态。失败时 `base_up_z=1.000`、IMU 角速度
`0.407 rad/s`，地面支撑门同时报告当前足印受支撑、状态为 `CLEAR`；唯一越界项是
`ground_nz=0.797 < 0.85`。该斜面估计还给出 `base_z=0.483 m`，明显偏离同一时段
定位持续报告的约 `0.263 m` 站立高度，二者来自同一拟合平面，不能拆开作为两份独立
倾倒证据。

本层只完成代码与历史日志诊断，不修改生产定位、任务判定、配置、launch 或官方文件，
也不运行新的 Gazebo。下一层只允许验证一个机制：把“地面法向与 IMU 直立姿态不一致”
解释为地面拟合无效，而不是立即累计 `BAD`；IMU 明确倾斜和可信平面上的异常机身高度
仍保持原来的三帧锁存失败。

## 3. 代码根因

### 3.1 楼面估计器与健康门的阈值语义不一致

`EstimateGroundPlane()` 的 `maximum_tilt_radians` 默认是 `0.75 rad`，因此法向
`z` 最低约为 `cos(0.75)=0.732` 的平面仍可能作为有效估计返回。持续健康门却把任何
已返回且 `ground_normal_z < 0.85` 的平面直接分类为 `BAD`。

所以 `0.732 ≤ ground_nz < 0.85` 形成了确定的冲突区间：

1. 上游认为拟合成功并返回高度和法向；
2. 下游不检查拟合与 IMU 是否一致；
3. 下游连续三帧后锁存 `health=false`；
4. MissionManager 正确地立即停车并写失败结果。

调低 `health_min_ground_normal_z` 只会移动冲突边界，不能修复证据语义；提高 RANSAC
最小法向又会同时改变世界系初始化和正常楼面估计，不是本问题的最小修正。

### 3.2 同一斜面派生的高度不是独立证据

`distance_from_base` 与 `normal_base` 来自同一组 RANSAC 内点和协方差精炼结果。
当法向已经与 IMU 直立姿态明显不一致时，`base_z=0.483 m` 不能继续作为可信机身高度。
本轮该值虽然仍在配置允许的 `0.14～0.60 m` 内，没有单独触发失败，但后续修正必须避免
把同一坏拟合拆成“法向异常”和“高度异常”两票证据。

### 3.3 真实倾倒仍有独立 IMU 证据

现有 `StanceHealthMonitor` 已把 `base_up_z` 低于阈值作为直接 `BAD`。历史可控侧倾
证据包括：

- `base_up_z=0.578`、`angular=4.827 rad/s`；
- `base_up_z=0.378`、`angular=3.956 rad/s`；
- `base_up_z=0.635`、`angular=2.641 rad/s`。

这些事件不依赖楼面拟合，即使地面估计缺失或被判无效，仍会在三帧后锁存失败。

## 4. 跨历史模式复核

从现存 `/tmp/stage*/mission.log` 与 `~/.ros/log/*/rosout.log` 中去重得到 7 组
`bad_frames >= 3` 模式：

| 模式 | 数量 | 当前代码状态 |
|---|---:|---|
| IMU 明确倾斜 | 3 | 保持 `BAD`，是真实姿态证据。 |
| 楼面缺失但 IMU 直立 | 1 | 既有代码已按直立证据处理，不再作为本轮候选。 |
| 只有角速度偏高 | 1 | 既有代码已改为有界 `UNKNOWN`。 |
| 门槛高度约 `0.175 m` | 1 | 既有健康下限已调整为 `0.14 m`。 |
| IMU 直立但返回低法向斜面 | 1 | 当前唯一未处理模式，即第 13.3 层失败。 |

这不是跨 seed 的概率统计，只用于证明当前失败具有独立于前三类历史问题的代码路径。
由于本轮没有原始点云，不能据此选择新的数值阈值。

## 5. 下一层预登记机制

第 13.6 层只验证“地面估计有效性与机身姿态异常分离”，不扫描参数：

1. `base_up_z` 低于现有阈值时仍立即累计 `BAD`。
2. 法向可信时，现有机身高度上下限仍累计 `BAD`。
3. `ground_normal_z` 低于现有健康阈值、但 IMU 明确直立时，把该帧的楼面法向和由其
   派生的高度视为无效地面证据，不把它单独计为倾倒。
4. 数据缺失时沿用当前安全语义；前方和足印支撑继续由独立生产地面支撑门 fail-closed。
5. 不按电梯、楼层、任务阶段、seed、世界坐标或转向命令增加豁免。
6. 不修改 `0.85`、`0.71`、三帧锁存或地面支撑门阈值。

定向测试必须覆盖：

- 本轮 `base_z=0.483`、`ground_nz=0.797`、`base_up_z=1.000`、`angular=0.407`
  不累计 `BAD`；
- 相同斜面但 `base_up_z` 明确倾斜仍三帧失败；
- 可信水平面上的趴地高度仍三帧失败；
- 连续缺失、角速度过高和锁存行为不回归；
- 第 8.2 层可控侧倾仍撤销 health/ready。

运行门槛：

- 先通过定位定向测试和两个参赛包构建；
- 再用固定 `seed=6946` 运行一次同配置双层定向闭环；
- 必须跨过原失败阶段并完成 `1→0→主入口→home`；
- 正常地面、电梯门槛和门区不得新增 health、DROP 或碰撞事件；
- 若第一次为环境启动失败，只允许同配置重试一次；
- 若两次算法运行仍在同一健康机制上失败，则停止并形成 Kimi 复核提示词，不扫阈值。
