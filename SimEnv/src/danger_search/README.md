# danger_search 正式运行入口

源层电梯开门后不再每10秒重置旧地图等待：局部几何模式直接刷新本次穿越证据，备用
直线预检与CROSS采用相同负障碍豁免；正障碍阻塞受30秒任务时间/180秒墙钟上限约束。

本包负责比赛任务编排、建图规划、感知、建筑交互、路径执行和结果写出。
定位由 `danger_search_localization` 提供；正式模式只消费比赛公开接口和参赛方内部
派生话题。

## 修改流程

本项目后续不安排自动测试或回归测试。修改前先理清调用链、状态转换、输入输出和失败降级，
再直接实施最小范围修改；测试源码和历史命令仅保留作查阅资料，不作为当前工作流程。必要的
编译、语法或生产边界检查只能作为静态确认，不得扩展成自动回归测试。

## 正式启动

先按团队运行手册启动官方 Gazebo 底座并让机器人稳定站立。底盘进入可消费
`/cmd_vel` 的 RL 模式后，再启动正式系统：

```bash
source /opt/ros/noetic/setup.bash
source devel/setup.bash
roslaunch danger_search danger_search.launch controller_ready_ack:=true
```

该确认参数只能在 `junior_ctrl` 已输出 `Entered RL /cmd_vel mode.` 后传入；
缺省值为 `false`，正式任务会拒绝启动。随后节点等待
`/danger_search/localization/ready=true` 后才创建 `MissionManager`，
因此定位未建立世界系时不会开始任务预算，也不会建立控制发布器。结果路径由
`generated_building/team_scene_info.json` 公布，formal 模式拒绝改写到其他位置。
运行期间定位持续用公开 `/scan` 和 `/trunk_imu` 发布姿态 health；连续异常会撤销
ready、停止输出新位姿，MissionManager 优先停车并写出失败结果。formal 模式不允许
关闭该门控。

短超时诊断入口不依赖 Gazebo 站立就绪：

```bash
roslaunch danger_search danger_search_smoke.launch \
  result_file:=/tmp/danger_search_smoke_detected.json \
  mission_summary_file:=/tmp/danger_search_smoke_summary.json
```

该入口使用 diagnostic profile，只验证启动、零速失效安全、超时和结果写出，
不能作为比赛正式入口。

## 离线评测

离线工具不属于本 catkin 包，也不会随 `danger_search` 安装。正式任务退出后才能按
工作区根目录 `tools/offline/README.md` 调用评分器。提交前可执行：

```bash
python3 tools/offline/check_production_boundary.py
```

质量不足、请求或回执超时都会在 3 秒内回退原流程。成功纠偏会清路径并同步危险源语义轨迹，

左右墙支持点和 `vector.z` 回执，并用带时间戳的 Livox、RGB 和位姿证据确认点云时空对应；还要比较
纠偏前后的门前姿态、足端支撑、路径首段和门区误障碍。质量门拒绝时应记录明确原因并有界回退，不能
为了产生 `applied` 事件而降低阈值。

## 当前速度与预算规范

- **巡航限速与防坠保护**：巡航与探索线速度上限为 `0.65 m/s`。按场景无空洞保证，0 层和电梯 ENTER/EXIT 的 CROSS 不启用防坠；其他高层阶段保留地面支撑门、零速与有界失败。传感器覆盖和时效仍有限，不能将该保护表述为绝对不会坠楼。
- **楼层预算**：单层探索超时为 `360.0 s`，单层最短探索时间为 `150.0 s`；测试运行脚本按 1/2/3 层将总预算覆盖为 `540.0 s`、`840.0 s` 与 `1280.0 s`。直接使用 YAML 启动时仍受 `mission/max_runtime` 的专项上限约束。
- **启动稳定等待**：启动脚本在切 stand 与切 RL 之间加入 2.0s 物理阻尼等待，降低四足接地冲击对传感器和控制器的影响。

## 当前电梯开门时序

开始换层时允许以 `call_elevator(..., open_doors=false)` 异步预呼梯，但不得在远距离阶段
调用 `open_door`。机器狗须先利用关闭的深色门板完成电梯近场几何刷新、回到刷新后的候梯点
并完成对准，随后才在 `OPEN_CURRENT_FLOOR_DOOR` 显式开源层门。目标层同样以
`open_doors=false` 升梯，服务成功后立即进入 `OPEN_TARGET_FLOOR_DOOR` 显式开门，不等待
调头完成。关门、升梯、目标开门期间均可原地对准；服务按源门关闭、升梯、目标开门的安全顺序
非阻塞轮询。目标出梯仍需对准完成、局部开口确认与正障碍检查同时通过。
到层后对准保留 12 秒上限；服务单次最多 30 秒任务时间或 180 秒墙钟，超时停车失败且不重发
可能仍在执行的请求；明确失败仍只重试一次。关闭局部穿越几何时，目标门后的地图阻塞等待
最多 30 秒，不再每 10 秒重置计时。

## 当前危险源与前沿策略

- 红球检测流程只由同步 RGB-D 完成颜色分割、深度反投影和固定半径 `R=0.15m` 几何拟合，再使用对应图像时刻的合法 PoseProvider 位姿转换到 world；Livox 不判断红色危险球，也不修正候选球心。单帧置信度在 `6.5m` 距离以内不施加距离折减惩罚（`distance_penalty_start: 6.5`），保证远距离真球保留 `0.88~0.98` 的高置信度。
- 跟踪器多帧确认采用基于球面拟合物理残差 RMSE 的**三级确认阶梯（Tiered Confirmation）**：
  1. **Tier 1（极高精度）**：`RMSE <= 0.005m`（5mm），置信度 `>= 0.70`，仅需 **1 帧** 即可进入 `CONFIRMED`（彻底解决机器狗在 `0.63m/s` 高速巡航下红球穿过视锥时间过短、无法凑满 4 帧而漏检的问题）；
  2. **Tier 2（高精度）**：`RMSE <= 0.015m`（15mm），置信度 `>= 0.70`，需 **2 帧** 即可 `CONFIRMED`；
  3. **Tier 3（常规兜底）**：`RMSE <= 0.035m`（35mm），置信度 `>= 0.75`，维持 **4 帧** 确认。
  实测中真实红球在 Gazebo 深度点云下的 RMSE 为 `0.20~1.33mm`，而场景红色干扰方块（边长 0.3m）拟合 RMSE 高达 `21.8~22.8mm`，阶梯阈值能完美区分真球与干扰物，杜绝误报。
- 为防止机器人在确认前压过近场红球，两个跨越至少 `0.08s` 的高质量帧会临时写入语义 `OCC`，若 `0.75s` 没有新帧即撤销。该覆盖按 `danger:<track_id>` 独立管理，半径为目标半径加现有地图膨胀半径，不能被自由射线、开门区域清理或定位 epoch 切换擦除。
- 稀疏地标纠偏回执会同步平移全部危险源历史观测与语义 `OCC`。若确认危险源安全圆已
  覆盖机器人当前格，任务立即停车、写出已有结果并显式失败，不会尝试穿越该区域。
- 已确认、未过期且属于当前楼层的危险源候选（任务层抢占置信度门限与 Tier 1 对齐为 `0.70`），在普通前沿路径执行期间可即刻抢占该路径，
  优先进入 `danger_approach_verification`；前沿收益、预取路径和旧到达状态会同步清除。
  接近奔跑中若距离已进入优质核验景深（`1.10m <= dist <= 1.80m`）且连续稳定捕获红球，将触发近场动态截断就地刹车切入对准与停稳核验（节省 3~5 秒多余奔跑）；未触发截断时踩中预设接近点后原地对准并取得核验阶段的新鲜多帧证据，接近失败不会把候选永久标记为已核验。
- 前沿最终评分以真实 A* 路径首段和累计拐角计算转向代价；正式
  `yaw_cost_weight=0.40`、`path_turn_cost_weight=0.70`，并将最高角速度限制为
  `0.90rad/s`。距离超过 `3.5m` 且预期收益低于 `16` 格的前沿在 A* 前后均被跳过（基于危险源物理尺寸及避让净空推导，避免机器人舍近求远回头探索绝无藏球可能的微小阴影），不能
  重新进入候选。
- 高层电梯门探索禁区（防轿厢回头振荡）：在非 0 层探索期间，当前楼层电梯门被注册为整个楼层探索周期的永久禁止半平面（`permanent_forbidden_half_plane`，半径 $\ge 3.0\text{m}$），前沿评估直接剪枝（`skip_in_forbidden_half_plane`）轿厢内部残留候选，杜绝出电梯后刚走几步又折返重新进梯的振荡。
- 前向避障梯形收腰通道（防转角擦边误刹停）：前向障碍物检测采用动态梯形半宽 `forward_obstacle_lateral_limit`。近身段（$forward \le 0.35\text{m}$）侧向半宽收缩至 $0.16\text{m}$，完美贴合 A1 机器狗机身轮廓，排除门框立柱与转角墙皮的擦边误检；远端（$forward \ge 0.60\text{m}$）保持 $0.22\text{m}$ 充足避障预警，根治拐角误急停卡死（corner freeze）。

运行日志中的 `danger_obstacle_sync`、`danger_obstacle_reprojected`、
`danger_source_overlap` 与 `frontier_selection` 候选分项用于复核上述策略；它们均不读取
真值数据。
