# 目标架构

源层开门确认后的通行与目标层采用相同分工：启用局部几何则由新鲜穿越几何完成预检，
不等待旧地图连通；备用CROSS直线仅忽略负障碍，OCC/BLACK仍有效。源侧地图阻塞等待
最多30秒任务时间/180秒墙钟，超时显式失败，不能周期重置。

## 修改与验证约束

本架构文档不再要求自动测试或回归测试。修改前先理清依赖、状态和失败降级，再直接实施最小
范围修改；文中历史测试和阶段验证仅作背景资料，不作为当前执行门槛。

## 依赖方向

```text
官方公开接口
  → runtime 适配层（SensorBuffer、PoseProvider、BuildingFeatureProvider）
  → 纯逻辑层（mapping、planning、perception、safety）
  → building/navigation 任务层
  → mission 编排层
  → CommandGateway 与 ResultWriter
```

上层可以依赖下层，下层不得导入任务编排、离线评估或真值工具。ROS 订阅、服务和文件访问集中在边缘适配层；算法核心优先保持无 ROS 副作用。

## ROS 包边界

- `danger_search`：Python 主系统。第 2 层已包含传感器缓存、统一位姿入口和定位健康/时间匹配决策。
- `danger_search_localization`：C++ 定位。第 2 层迁入固定版本 KISS-ICP C++ 分发和定位组件；历史定向测试不属于当前修改门槛，不引入上游 ROS wrapper、Python 包、评测 notebook 或 CI；上游自带的 `metrics` 源码不进入默认构建、链接、安装和启动链。
- `danger_search.mapper`：每层独立 2.5D 占据栅格，只接受第 2 层已配准世界系点云；UNKNOWN、BLACK、OCC 一律不可通行。
- `danger_search.planner`：单层八邻域 A*，显式区分到达、确定不可达和预算耗尽，禁止对角切角。
- `danger_search.frontier`：前沿提取、安全落点、有限候选规划、评分和短期失败黑名单；不发布速度或切换任务状态。
- `danger_search.navigator`：纯跟踪计算加 ROS 边缘发送器；路径、恢复、停车和保活命令都经过同一个 `_publish` 出口。
- `danger_search.ground_support_gate`：最终速度出口前的停车包络和支撑状态机；不改地图、不重规划，也不自行发布速度。
- `danger_search.ground_support_runtime`：支撑线程到主线程的证据队列、Gate 状态镜像和任务层重试账本；不重新判定安全，也不发布速度。
- `danger_search.ground_support_coordinator`：拥有 GroundSupport Gate、ShadowSupport 与反馈队列的生命周期；任务层只读取协调结果，安全判定仍属于 Gate。
- `danger_search.perception_runtime`：拥有 SensorBuffer 与点云/RGB-D 独立消费游标；不判断楼层、不写地图。
- `danger_search.map_update_runtime`：拥有 Mapper、危险源检测器、门板检测器和跟踪器；只在主线程提交地图/检测更新，并返回冻结摘要。
- `danger_search.floor_transition_runtime`：拥有换层期间唯一楼层作用域守卫；只根据服务确认和新里程计决定是否允许楼层数据写入。
- `danger_search.door_observation_runtime`：主入口门洞的跨帧确认和近场刷新拒绝分类；不读 ROS、不调用服务。
- `danger_search.return_home_planner`：冻结地图/轨迹上的返航 A*、候选验证和后台执行器；不持有正式地图引用、不切换任务状态。
- `danger_search.mission_config`：ROS 参数、公开场景能力和接口白名单的唯一加载边界；输出启动时配置快照。
- `danger_search.mission_node_runtime`：ROS 节点初始化、订阅、定时器、墙钟 watchdog 和 shutdown 生命周期；不决定任务状态。
- `danger_search.mission_reporting`：结果文件、运行摘要、状态/地图诊断话题和结构化日志的唯一输出边界。
- `danger_search.progress_monitor`：前沿选择与位姿进度的诊断状态机；只产生诊断/cooldown，不修改地图或任务状态。
- `danger_search.red_sphere_detector`：同步 RGB-D 的红色分割、深度反投影、已知半径模型提议和高斯-牛顿几何精炼；只有提供对应图像时刻的合法刚体 `camera_to_world` 才输出逻辑 world 候选。Livox 不参与红球类别判断或候选球心修正。
- `danger_search.detection_tracker`：危险源候选的多帧关联、按置信度/距离平方/拟合 RMSE 加权融合、质量确认和空间 NMS；同一输入帧对每条轨迹最多贡献一次命中。
- `danger_search.rgbd_door_detector`：深色门板的平面/尺寸验证和开门视觉变化；只输出匿名几何观测，不解释门 ID、不调用服务。
- `danger_search.building_control_client`：公开 door/elevator ID、服务权限和运行时传感器几何的唯一结合点；异步服务响应不直接改地图。
- `danger_search.local_semantic_detector`：从局部世界系点云提取门洞与轿厢结构；正式配置禁止真值邻近回退。
- `danger_search.navigation_context`：导航子任务每个 tick 的冻结依赖合同；任务不能反向读取或修改 `MissionManager` 私有状态。
- `danger_search.navigation_tasks`：普通导航、过门和乘梯的非阻塞子状态机；只通过显式 `NavigationTaskContext` 使用 Mapper、PathFollower、感知确认和建筑客户端。
- `danger_search.exploration_runtime`：无前沿逃逸、前沿惯性和探索进展的有界账本；不决定换层或返航。
- `danger_search.elevator_observation_runtime`：电梯门板、刷新和开门确认的跨帧状态；不调用服务、不发布控制。
- `danger_search.return_home_runtime`：返航异步规划、局部失败段和受控后退反馈；不写任务结果、不切换顶层状态。
- `danger_search.mission_manager`：10 Hz 顶层状态机；按定位健康、感知更新、安全门控、子任务和顶层决策的固定顺序推进，只编排上述运行时模块，不直接拥有 ROS 感知缓冲、Mapper/Detector、楼层守卫、GroundSupport 组件或子任务内部账本。

## 离线工具边界

- 真值评分、bag 回放、Gazebo 状态分析和批量调参只能位于工作区根目录
  `tools/offline/`，不得进入任何 catkin 包。
- `danger_search` 的 Python 安装清单严格只有 `scripts/danger_search_node`；Python 包、
  setup、CMake 和 launch 均不得导入或安装离线工具。
- 环境自带的 `building_obstacles/evaluate_danger.py` 只允许在正式任务退出后单独执行，
  其真值输入和评测输出不得回流到同一轮生产状态。
- `tools/offline/check_production_boundary.py` 在提交和最终验收前重复检查上述边界。

职责迁移后删除旧字段和测试鸭子接口，不在 `MissionManager` 上保留兼容 setter；测试直接构造运行时所有者或显式上下文。

## 不变量

- 位姿只能来自统一 `PoseProvider`。
- 建筑公开信息只能来自 `BuildingFeatureProvider`。
- 生产 `/cmd_vel` 只能有一个最终发送入口。
- 生产包不能导入离线评估或真值工具。
- 缺失、陈旧、非法或未授权输入必须 fail-closed。

## 定位就绪契约

- 定位节点启动后立即锁存发布 `/danger_search/localization/ready=false`。
- 只有连续 8 帧公开 `/scan` 与 `/trunk_imu` 同时满足站立高度、楼面法向、机身朝向和角速度约束，才建立世界系并开始发布里程计与配准点云。
- 初始化旋转取该时刻匹配的 `/trunk_imu` 世界姿态，不用出生 yaw 覆盖站立后的姿态；公开出生位姿提供 XY，Livox 楼面提供高度。正式 IMU 后端缺少匹配 IMU 不初始化；无 IMU 的非正式组合仍保留原出生姿态/楼面路径。`localization_world_initialized` 记录来源、时间戳和初始位姿。
- 腹部着地时即便楼面法向和 IMU 朝向近似竖直，只要 `base_z` 不在 `0.20～0.55 m` 内就不得初始化。
- 世界系建立后，定位节点逐帧从公开 `/scan` 重新估计楼面高度和法向，并与时间匹配的 `/trunk_imu` 共同监控姿态健康；连续异常时撤销 `ready`、发布 health=false，并停止发布该帧里程计和配准点云。
- 缺失或非有限的楼面/IMU 证据按异常帧累计，不能沿用上一帧健康值放行。
- 不健康状态默认锁存，避免重锚定导致世界系跳变；诊断模式可通过参数关闭该锁存或 health 检查。
- 里程计速度使用一秒位姿窗口和死区估计；原始位姿不做静止锁定，避免把真实低速运动误判为零速。
- Python `PoseProvider` 只接受有限、四元数有效且时间严格递增的内部里程计样本；任务层必须通过 `LocalizationRuntime` 判断陈旧、待匹配和过期状态。
- MissionManager 在 health=false 时优先于里程计陈旧判定立即停车、取消成功资格并进入失败写出；定位可用但 health 持续缺失时也必须超时失败。
- 定位线/角速度死区分别为 `0.05 m/s`、`0.03 rad/s`；地面支撑门的停稳阈值不得小于对应死区，否则构造时失败。
- 地面支撑与防坠硬保护：巡航限速 $0.65\text{ m/s}$；即使 `unknown_support_hold_enabled=false`，一旦四足足端检测到下方无支撑（悬崖/空洞），强制输出零速并在超时后触发 `SUPPORT_PATH_UNAVAILABLE` 重规划，绝不坠楼。
- 用户确认 0 层及电梯 `ENTER_CABIN/EXIT_CABIN` 的 `CROSS` 一定无空洞，跳过全部支撑边界/未知支撑/显式 DROP 防坠判定；高层 CROSS 结束后恢复。速度包络、实体障碍、定位与站立健康保护不豁免，楼层歧义时不套用 0 层保证。

## 定位后端与传感器职责

- 正式启动固定使用 `adaptive_shared_map`，不按任务阶段在不同定位后端之间切换；
  `rgbd_livox` 仅保留为显式回退。
- `/trunk_imu` 在正式后端中提供时间匹配的绝对姿态增量，并参与初始化与持续 health；
  不对加速度做位置积分。旧 `imu_constrained` 诊断后端仍保留加速度积分，但不作为正式
  方案。
- 回退后端 `rgbd_livox` 用 RGB-D 帧间 GICP 提供连续平移，用 Livox 帧间 GICP 在深度
  陈旧时补位，并始终用 Livox 局部结构地图校正慢漂。RGB-D 同时继续承担危险源、门和
  电梯视觉感知。
- `livox_imu_local_map` 是默认关闭的候选后端：IMU 固定旋转，`/scan` 局部结构地图估计
  平移，`/cmd_vel` 仅提供优化初值。位姿和地图以同一事务提交，结构不足或运动学超限时
  保持上一已接受位姿且不污染地图；RGB-D 不参与该后端的定位，但仍完整用于感知。
- 正式 `adaptive_shared_map` 后端采用 G3 默认：IMU 始终确定姿态，Livox 维护唯一局部
  地图、提供平移候选和约 `10 Hz` 输出时钟，`max_range=15m`。定位节点默认不订阅 RGB-D
  深度点云，RGB-D 仍由任务节点用于危险源、门和电梯感知；显式设置
  `adaptive_rgbd_localization_enabled:=true` 才恢复 RGB-D 与 Livox 只读同一地图生成候选。
  这仍是固定后端内部的测量选择，不允许按任务阶段切换。只有当前 Livox 帧可以按最终
  正式位姿提交地图；Livox 候选无效时不发布新 odom/cloud，让既有陈旧检测 fail-closed。
- Stage15 固定 seed 验证中，早期候选的最大航向误差为 `0.00294 rad`，但平移 RMSE 为
  `0.05598 m`、P95 为 `0.11669 m`，且二层闭环失败。因此当时不足以晋级，也不得据
  单轮日志增加残差阈值。
- Stage16 的 `adaptive_shared_map` 在 seed `8127/1612/8072` 上都完成闭环。seed `8072`
  按基线实际走过的同一 `1.529 m` 路程比较，RMSE、P95 和末端误差分别改善 `24.3%`、
  `15.8%` 和 `1.9%`；原相同时间比较混入了不同运动进度，不能作为退化证据。三轮
  RGB-D 选中占比仅约 `3.7%～12.5%`。
- Stage17 当前取得 `8/20` 个有效 seed，全部完成闭环、定位诱发失败为 0，`7/8` 的
  RMSE 小于 `0.1 m`，但没有一轮小于 `0.05 m`；seed `1612` 的末端误差
  `0.2529 m` 超过冻结的 `0.20 m` 硬门，因此矩阵仍是 `insufficient_evidence`，且即使
  补齐也无法通过原全部硬门。按用户明确决策，正式默认已直接切到
  `adaptive_shared_map`；这表示接受当前风险，不表示冻结矩阵已通过。需要回退时显式传入
  `localization_backend:=rgbd_livox`。Stage17 工程验收状态为通过，剩余矩阵仅用于量化
  残余风险。
- 当前 `/scan` 每帧只有统一时间戳，没有逐点采样时间；现有 `/livox/lidar2` 的
  `offset_time` 不是传感器采样时间。未修正公开输入语义前，FAST-LIO2 的逐点去畸变
  前提不成立，不能直接接入生产链。
- 定位 odom、配准点云、调试地图、原始/跟踪路径和局部目标必须共享同一个全局
  `frame_id`。正式模式固定为 `world`，相对原点 smoke 固定为
  `danger_search_relative`；禁止用无物理意义的静态 TF 掩盖消息标签错误。

## 建图与规划不变量

- 点云写障碍必须先于同帧自由射线；自由射线遇到 OCC/BLACK 立即停止。
- 普通 VISITED 只能覆盖 UNKNOWN/FREE/VISITED，不得擦除 OCC 或安全 BLACK。
- 每层实际行驶轨迹的 `0.25m` 核心带持久保存为保护 VISITED；距离机器人超过 `2.0m`
  的新正障碍不得覆盖该带。`2.0m` 内仍需 3 个点云代次、2 个相隔至少 `0.15m`
  的观测位姿才能阻挡；BLACK、NEGATIVE、严格反证和动态开门清除仍保持原语义。
- 轨迹带只能连接间距不超过两个保护半径的连续位姿；定位跳变不得生成永久自由通道。
- A* 允许把 UNKNOWN 起点修正为当前机器人自由格，但 OCC/BLACK 起点必须直接判定不可达。
- 阻塞目标的替代格按几何距离选择；规划预算耗尽不能累计成不可达或黑名单。
- 前沿候选必须先找到满足障碍净距与未知退让的已知自由落点，再由 A* 确认可达。
- 距离大于 `3.5m` 且预期收益小于 `30` 格的远距离小前沿在规划前直接剪枝；后续 A*
  结果解析不得将其重新激活。
- 正式配置固定 `async_planning_enabled: false`、`opportunistic_replan_period: 0.0`。
  保留的预规划基础设施不是正式并发执行许可，任务运行中不得边跑边抢占换道。
- 高层探索前沿禁区不变量：非 0 层探索期间当前楼层电梯门注册为该层探索周期的永久禁止半平面（`permanent_forbidden_half_plane`），`skip_in_forbidden_half_plane` 持续剪枝轿厢内部前沿候选，禁止出梯后掉头重新探索轿厢。

## 路径执行与安全不变量

- `PathFollower` 只能向白名单输出 `/cmd_vel`；原始路径、跟踪路径和局部目标只能写入 `/danger_search/*` 内部诊断话题。
- 前向障碍物观察走廊采用动态梯形收腰（`forward <= 0.35m` 时半宽为 `0.16m`，`>= 0.60m` 时为 `0.22m`），贴合 A1 机身物理包络，严禁门框立柱或转角擦边点云误触发正前向减速或零速急停。
- 路径点、当前位姿、算法请求命令或安全门返回值出现非有限数时，最终输出必须为零；非法位姿同时清除当前路径并报告 `STUCK`。
- 单点路径在目标容差外仍是有效活动路径，必须朝该点跟踪，不能访问不存在的下一段。
- 地面支撑门开启且尚无有效评估时，非零命令进入 `STALE_DATA_HOLD`，不得以“尚未发现缺口”为由放行。
- 支撑不足后的定时保活只能重发已经过门控的零速；恢复放行必须等待新的控制 tick，不能重放停车前旧命令。
- 正式控制与防坠基线固定为 `max_linear: 0.65m/s`、
  `boundary_hold_margin: 0.40m`、`observation_hold_timeout: 3.0s`；不能通过提速、缩小
  边界余量或缩短观察停车来换取探索时间。

## RGB-D 感知不变量

- RGB、深度、内参和 `camera_to_world` 任一缺失、非有限、尺寸不匹配或不是合法刚体变换时，检测返回空集合，不退回最新位姿、TF 或真值。
- 红色外观只能产生候选；危险源必须使用公开先验半径 `R=0.15m` 的几何残差模型，单侧球冠使用沿视线后移 `R` 的物理初值，再以高斯-牛顿精炼中心，不能退回自由半径代数最小二乘作为正式定位结果。候选评分在 `6.5m` 内不施加距离硬折减，保证远距离真球高置信度。
- 跟踪器确认支持基于球面拟合物理残差 RMSE 的**三级阶梯确认规则**：极低残差（`RMSE <= 0.005m`，置信度 `>= 0.70`）只需 **1 帧** 命中即可 `CONFIRMED`；高精度残差（`RMSE <= 0.015m`，置信度 `>= 0.70`）需 **2 帧** 命中；常规残差（`RMSE <= 0.035m`，置信度 `>= 0.75`）维持 **4 帧** 命中。不同阶梯的命中数均代表不同 `DetectionTracker.update` 独立时间戳帧，同一帧多个相邻轮廓不得跨帧伪造或提前确认目标。
- Tracker 的位置融合按置信度、观测距离平方和拟合 RMSE 加权；远距候选满足触发条件（任务层抢占门槛与 Tier 1 对齐为 `0.70`）时，
  任务层可即刻抢占普通前沿路径并导航至约 `1.3m` 观察距离复核。该机制仍受 A*、障碍和地面支撑门控，不能盲目直线靠近。
- 感知核心不自行添加楼层高度。若定位垂直参考为 `floor_local`，任务适配层只在构造 `camera_to_world` 时增加一次逻辑楼层 z 偏移；`absolute` 模式不增加。
- 门板观测只有几何位置、朝向、尺寸和开闭证据；与公开 door ID 的关联属于第 6 层任务边界。

## 建筑交互与导航任务不变量

- 服务调用前必须再次校验 door/elevator ID 和 served floors 属于公开场景集合；运行时几何不能给未知 ID 扩权。
- 门、电梯厅的 XY-yaw 和宽度必须来自有限的运行时传感器注册值，公开场景文件不提供空间目标。
- 普通 `NavigateToPose` 的 A* 确定不可达返回 `FAILED`；预算耗尽零速等待下一轮，二者都不得退化成直线穿越 OCC/BLACK。
- 过门和进出轿厢的直线跨越只允许在专用子状态机内，经段碰撞检查、朝向对齐、严格端点容差和真实位姿进度监督后执行。
- 主入口远场门洞只建立入场轴和门面；公开服务开门后必须以新鲜近场点云连续确认净空并更新等待/通过点。该刷新不改变普通房门状态机。
- 电梯门由传感器确认打开后，进厢和出厢都必须用 3 个不同 Livox 点云代次刷新本次穿越轴；
  该几何只属于当前 `TakeElevator`，不覆盖长期注册门或定位地图。旧注册中心偏移只记录诊断，
  目标层当前位姿与新轿厢中心偏差超过 `0.80m` 时关闭失败。
- 局部门洞必须符合当前 POSITION 站位的物理距离：进厢使用 `0.80±0.35m`，出厢使用
  `0.95±0.35m`。稳定但过近的轿厢内部结构不能作为门框，检测器必须继续搜索距离窗口内
  的真实门平面。
- 已确认的本地电梯门洞允许清理本次门条带中的旧 OCC；提交 CROSS 前仍须检查当前点云的
  有限扫掠走廊。门面残留可在已确认开口内排除，轿厢侧墙和走廊内实体障碍不得整体忽略。
- 服务返回 accepted 只表示交互请求成功；清门区、确认开口和切换逻辑楼层仍需本地传感器证据。
- `/call_elevator` 只移动轿厢；源层和目标层都必须显式调用对应
  `open_door` 后再等待局部开口证据。首次 15s 确认超时只允许一次重试：
  源层停车复核锚点、等待至少 0.5s 后的新 Livox 帧、重新对准并重发呼梯/开门；
  目标层保持在轿厢内，只等待新帧并重开门。重试 10s 后仍无证据则显式失败。

## 稀疏静态地标纠偏不变量

- 主入口另有独立的固定几何纠偏观察器：只消费当前连续定位段的注册 Livox 点云，
  以固定入口合同（中心 `(0,0)`、外墙 `y=0.09`、缺口宽 `2.0m`）估计有限 XY/yaw 平面变换，
  不读取生成场景文件，也不把室内布局当作先验；开局和开门后过门前各最多尝试一次。
- 入口默认 `entrance_geometry_apply_correction=false`，仅一次取样观察，不停车等待或请求纠偏。
  显式开启注入后仍须满足 3 帧、两侧支持和 SE(2) 质量门槛；回执后使用新时间戳的真实合法位姿
  检查危险源重叠，不能再次平移已纠正的位姿。回执或新位姿超时意味着坐标事务不确定，停车失败，
  不能当作未应用而继续使用旧地图。观察等待与回执等待各有上限，匹配计算另计。
- 主入口和 0 层电梯在首次合法传感器注册时，各冻结一个 Livox 静态结构关键帧；
  门板动态条带不进入锚点，后续语义门几何刷新不覆盖关键帧。
- 稀疏地标重定位只使用当前楼层、当前定位 epoch 的 3 帧已配准 Livox 点云；主入口返航复核与
  固定几何入口纠偏是两条独立路径，前者仍不参与开局门流程，
  电梯锚点只在其冻结楼层复核。点数、重叠率、P70 残差、唯一性、连续帧离散任一不合格都拒绝注入。
- 纠偏以世界系左乘 SE(2) 变换提交，平移和 yaw 分别受配置上限约束。Python 侧先检查里程计速度，
  C++ 定位节点再检查新鲜度、`/cmd_vel` 和 IMU 角速度；通过后在同一临界区变换已发布位姿和 Adaptive Shared Map，
  再用带序号回执切换 `PoseProvider` 连续性 epoch。`Vector3Stamped.vector.z` 表示 yaw 修正；无回执不得当作纠偏成功。

## 任务编排不变量

- ROS 节点初始化后任务预算只使用 ROS 时间；读取异常显式失败，不得回退墙钟混用时间域。
- 电梯结果只在任务 `DONE` 后记真，`FAILED` 记假，发起和执行中保持未知。
- 楼层估计与逻辑楼层持续不一致时阻止楼层数据写入；对齐超时必须停车并进入结果写出，不能永久零速等待。
- 无预算返航 A* 只读取栅格与历史轨迹快照并在后台运行；主 tick 在结果就绪前持续发送安全零速，过期楼层或目标的结果直接丢弃。
- 当前楼层确认危险源优先于普通前沿和软换层决策；普通返航路径也可主动核验，但不打断门、
  电梯、退避、恢复、外部对准、安全失败返航或安全闭锁。探索准入预留单次核验总时限、
  接近路线返回原位的时间、原位返航估计与缓冲；每次重试重新计算。返航途中核验不预扣预算。
