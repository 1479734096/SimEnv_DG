# 成功运行与失败运行分歧分析

## 对比对象

- 成功运行：`SimEnv/results/runs/20260711_132738_seed_42/`
- 失败运行：`SimEnv/results/runs/20260711_124922_seed_42/`
- 配置相同：`config/medium_time_budget_test.yaml`
- 随机种子相同：`42`

## 关键差异

| 指标 | 成功运行 | 失败运行 |
|---|---|---|
| 探索时间 | 263.5s | ~200s 后基本停滞 |
| 正确识别 | 4/6 | 1/6 |
| 返航成功 | True | False |
| 长停比例 | 0.03 | 高 |
| 最大离家距离 | 23.09m | ~14.5m |

## 失败运行退化循环

失败运行在仿真时间约 t=120s 后陷入局部死循环：

- 机器人位置锁定在 `(-5.79, 13.38)`，航向约 2.38rad。
- 控制器报告 `goal_reached`，`path_active=False`，`path_size=0`。
- 下一秒 `_tick_explore` 重新选择同一附近目标 `(-6.05, 13.55)`。
- 目标到机器人距离仅 0.31m，规划路径长度仅 0.38m，小于控制器 `goal_tolerance=0.35m`。
- 控制器立即再次认为“已到达”，不输出有效速度，循环往复。
- 从 t=120.06s 到 t=200s，日志中每秒约 10 次重复出现同一 `frontier切换` 记录，累计约 1100 次。

异常模式可抽象为：

```
goal_reached
→ path cleared
→ 下一 tick 重新选择当前附近同一区域目标
→ 实际位移接近零
→ 反复循环
```

## 成功运行同期行为

在失败运行陷入循环的同一仿真时段（t=100s~200s），成功运行已移动到不同区域：

- t=100s 位于 `(-4.09, 20.55)`
- t=130s 位于 `(-7.35, 10.62)`
- t=190s 位于 `(0.70, 14.74)`

说明失败运行并非全局不可达，而是在一个局部近邻 frontier 处被反复选中并立即判达。

## 根因

任务层缺少对“反复选择同一近邻目标但无实际进展”的监督。控制器按 `goal_tolerance` 正确判定到达，但 frontier 选择器不断返回几乎相同的目标，形成高频空转。

## 修复方向

第一版仅增加任务层最小进度监督：

1. 记录近期选中的目标位置和机器人位姿。
2. 检测短时间内同一区域目标被反复选中、且机器人实际位移很小。
3. 触发后对该局部区域设置短期 cooldown，清除当前路径，尝试选择空间上不同的 frontier。
4. 不直接返航或换层，交由现有无-frontier 处理流程和时间预算决策。
5. 对重复日志限频，避免上千条重复记录。

第一轮不修改 frontier 生成、mapper、controller 参数，也不提前按 information_gain 或 unknown 格子拒绝目标。
