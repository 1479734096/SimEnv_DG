> 版本号 `v2.0`，基于团队成员的测试反馈，完善了部署步骤与注意事项。

---

#### 一、环境要求

- **硬件要求**：配备 `NVIDIA GPU`

- **软件要求**：

  - 操作系统 `Ubuntu 20.04`
  - 仿真平台 `Gazebo 11`，搭配 `QGC 4.3.0` 使用
  - 飞控固件 `PX4 v1.13.2`

  - `Python 3.8` 及以上版本
  - `NVIDIA GPU` 驱动相应版本的 `CUDA` 与 `cuDNN`
  - `requirements.txt` 中所要求的 `pip` 库
  - `Python` 接口所需库 `rospkg` 和图像处理桥接库 `cv_bridge`

---

#### 二、部署步骤

1、在 `scripts` 目录中打开终端，执行以下命令安装所需环境。

```bash
pip3 install -r requirements.txt
sudo apt install python3-rospkg
sudo apt install ros-noetic-cv-bridge
```

---

#### 三、启动步骤

1、根据选手手册，启动仿真环境与赛题程序。

2、在 `scripts` 目录中打开两个终端，同时启动两个起飞主程序。 四旋翼无人机将在垂起无人机锁桨降落后起飞。

```bash
python3 vtol_take_off.py
```

```python
python3 iris_take_off.py
```

#### 五、注意事项

1、若在启动仿真环境后，终端中持续打印如下字样，是由于 `PX4` 在遥控器（RC）信号丢失情况下触发失控保护。

```bash
Failsafe mode activated
Failsafe mode deactivated
```

本问题可在 `QGC` 中设置以下参数解决：

- 设置 `RC Loss Failsafe Trigger` 中 `Failsafe Action` 为 `Hold mode`
- 设置 `COM_RCL_EXCEPT` 为 `4`

2、若问题1解决后，`vtol` 或 `iris` 仍无法起飞，分别执行以下命令

```bash
rostopic echo /standard_vtol_0/mavros/state
rostopic echo /iris_0/mavros/state
```

若终端中持续打印如下字样，可知虚拟无人机当前处于 `OFFBOARD` 模式但仍未解锁，从而无法起飞。

```bash
connected: True
armed: False
guided: False
manual_input: False
mode: "OFFBOARD"
system_status: 3
```

本问题可执行以下命令解决：

```bash
rosservice call /standard_vtol_0/mavros/cmd/arming "value: true"
rosservice call /iris_0/mavros/cmd/arming "value: true"
```
